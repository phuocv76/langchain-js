Phương án 1 · langgraphjs dev / Agent Server

LangGraph Server mặc định

  • Zero code dịch AG-UI — CopilotKit có adapter LangGraphAgent sẵn
  • Nhưng D1 không có cửa — server gán đè checkpointer khi load graph, không config nào can thiệp được
  • Bản JS (langgraphjs dev) là dev-only: queue trong RAM, 1 instance, không auth
  • Bản production (Agent Server) là container Python đóng nguồn — không patch được
Loại — trừ khi từ bỏ hoàn toàn D1 cho checkpoint. Docs: “Do not configure these in your graph code.”
langgraph-api · graph/load.mts
// Server load graph — ghi đè vô điều kiện:
if (options?.checkpointer !== undefined) {
  compiled.checkpointer =
    options?.checkpointer ?? undefined;
} else {
  compiled.checkpointer = checkpointer;
  // ^ saver nội bộ của server,
  //   D1CheckpointSaver bị thay thế
}

Phương án 2 · Agent Server production

Server + Postgres — chính thống, nhưng rời D1

Được gì
  • Zero custom code runtime — bridge xoá, adapter thư viện lo AG-UI
  • Kiến trúc được LangChain hỗ trợ chính thức, ổn định theo semver
  • API threads/runs/crons đầy đủ + LangGraph Studio
  • Transcript/durable memory vẫn giữ được ở D1 (nằm ngoài checkpointer)
Mất gì
  • Checkpoint rời D1 → Postgres do server quản (đảo quyết định D1 của team)
  • Thêm 1 service + 1 database phải deploy & vận hành
  • State tách 2 engine: checkpoint Postgres · transcript D1 — delete phải đuổi cả hai
  • Auth phải làm lại theo cơ chế custom-auth của server
Chọn khi “không bridge” là ưu tiên số 1 và team chấp nhận bỏ D1 cho checkpoint.

Phương án 3 · Hiện tại (v2)

AG-UI Bridge in-process + D1

Được gì
  • D1 cho mọi thứ — checkpoint + transcript một database
  • Ít tầng nhất: 1 process agent + worker, không service phụ
  • Đã chạy, đã có test, multi-tenant theo user Firebase
  • Không phụ thuộc API experimental hay internal của ai
Mất gì
  • ~360 dòng bridge tự nuôi (agui-bridge.ts) — dịch event LangGraph → AG-UI
  • Lệch chuẩn: không có API threads/runs kiểu LangGraph platform
  • Mỗi nâng cấp CopilotKit/LangGraph phải tự kiểm tra lại bridge
Baseline an toàn — phương án ít rủi ro nhất thỏa mãn D1; chi phí duy nhất là sở hữu code dịch.

Chốt

Chọn theo thứ bạn không muốn từ bỏ

  • Ưu tiên ổn định, không đụng gì → giữ Phương án 3 (bridge + D1). Chi phí duy nhất: sở hữu 360 dòng đã có test.
  • Yêu cầu cứng “không bridge” + giữ D1 → Phương án 4. PoC đã chứng minh chạy thật; đổi lại sống cùng API experimental (pin version + regression test) và làm nốt ThreadSaver, auth, HITL.
  • Sẵn sàng bỏ D1 cho checkpoint → Phương án 2, kiến trúc chính thống ít code nhất; transcript vẫn ở D1.
  • Phương án 1 chỉ tồn tại làm dev tool — chính là pnpm studio hôm nay, không phải lựa chọn production.
Đề xuất: quyết định giữa 3 và 4 sau khi PoC bước 3 (HITL / frontend tools) — đó là ẩn số cuối cùng còn lại của phương án 4.
