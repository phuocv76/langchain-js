conventions that matter

  • Env validated with Zod at boot — bad config fails fast, per-process rules
  • Middleware compiles into real graph nodes — new agents reuse auth/memory blocks as-is
  • Tools take identity from the verified context, never from model arguments
  • Secrets live only in .env / wrangler secrets — never committed, never logged
  • Kebab-case files: *.tool.ts · *.controller.ts

adding an agent

  • src/agents/<name>/graph.ts → register in langgraph.json + graphs/registry.ts — done

Designed to be extended

Three drop-in points

  • New tool — add tools/<name>.tool.ts, register in tools/index.ts. Zod schema in, typed result out.
  • New agent — add agents/<name>/graph.ts, register in langgraph.json + graphs/registry.ts, point the UI's agentId at it.
  • Tool preview — one useRenderTool hook per tool renders its result as structured cards in the side panel.
  • Durable memory — ships in-repo (D1 worker). Set MEMORY_WORKER_URL to enable; unset, it no-ops cleanly.

Engine memory — full graph state per thread, lets the agent resume any conversation. Transactional, official LangGraph server code.

Decisions & gotchas

the parts you'd otherwise learn the hard way

Decisions we already made

Four calls, and why

  • Own the chat data — dropped CopilotKit Intelligence (SaaS); transcripts live in our D1. HR conversations never leave company infrastructure.
  • Official persistence code only — Postgres checkpoints via the LangGraph server image; no hand-rolled savers or protocol adapters to maintain.
  • Memory is best-effort — the worker can be down and chat still works; correctness-critical state stays transactional in Postgres.
  • Identity is server-minted — verified Firebase token → sanitized x-agent-*; the model can never choose whose data it touches.

Read before touching

Three gotchas, all documented in-repo

  • Dependency pins — pnpm-workspace.yaml forces one LangChain instance and pins LangGraph 1.4.4. Upgrading blindly re-breaks graph construction ("Channel already exists"). See state.ts comments.
  • LangGraph server must stay private — :2024 trusts identity headers; anyone who can reach it can impersonate anyone. Localhost / private network only.
  • Monorepo Docker builds — the official langgraphjs build runs npm i and breaks on workspace:*; use our Dockerfile.langgraph (pnpm, workspace-aware) instead.
