03 · Workflow — một tin nhắn đi qua 6 trạm

Browser → … → D1, tất cả trong một process

B1 Verify Firebase ID token → JWKS verify → xóa Authorization, gắn header x-agent-* sạch agent-user-auth.ts
→
B2 Adapter Runtime tạo LangGraphAgent mỗi request, trỏ loopback 127.0.0.1:4000/langgraph + Bearer của user intelligence.ts
→
B3 Re-verify + ALS requireAgentUser lần 2 → AsyncLocalStorage(userId) bọc toàn bộ request langgraph-embed-app.ts
→
B4 Inject claims POST tạo run: strip x-agent-* của client, ghi claims verified vào config.configurable withVerifiedRunClaims
→
B5 Graph chạy middleware đọc claims → agentContext → tools gọi space-api bằng token user durable-memory.ts
→
B6 Persist checkpoint + thread metadata + transcript → memory worker → D1, scope theo user d1-*-saver.ts
Điểm khác biệt với default: B3, B4 là code của mình (server chuẩn tự làm); B6 là D1 thay vì Postgres. B1, B2, B5 giống mọi app CopilotKit khác.

04 · B1 — cổng danh tính duy nhất

requireAgentUser

  • Verify chữ ký token bằng Google JWKS — không cần Admin key.
  • Xóa Authorization rồi mới gắn claims — downstream không bao giờ thấy credential gốc lẫn header giả từ client.
  • Token đã verify đi tiếp dưới tên x-agent-access-token để tools gọi API sản phẩm as-user.
  • Chặn theo domain email (ALLOWED_EMAIL_DOMAINS) + bắt buộc email verified.
middleware/agent-user-auth.ts 
const decoded = await verifyFirebaseIdToken(
  idToken, env.FIREBASE_PROJECT_ID);

headers.delete('authorization');
headers.set('x-agent-user-id',    user.userId);
headers.set('x-agent-user-email', user.email);
headers.set('x-agent-roles',      rolesEncoded);
headers.set('x-agent-access-token', idToken);
// danh tính LUÔN từ token verify,
// không bao giờ từ client tự khai

05 · B2 — adapter stock, không bridge

intelligence.ts

  • Mỗi request một agent — vì token của từng user khác nhau, không share adapter được.
  • URL là loopback về chính BFF: về mặt code giống hệt gọi LangGraph server ngoài, nhưng không có network hop thật.
  • Chú ý: không gửi claims qua assistantConfig — adapter 0.0.42 lọc rơi key lạ (bug đã gặp thật, xem slide 08).
config/intelligence.ts 
agents: ({ request }) => {
  const user = identityFromRequest(request);
  return ... new LangGraphAgent({
    deploymentUrl:
      `http://127.0.0.1:${AGENT_PORT}/langgraph`,
    graphId: agent.graphId,
    headerFactory: () => ({
      Authorization: `Bearer ${user.accessToken}`,
    }),
  });
}

06 · B3 — những gì embed thiếu, shim bù

Assistants shim (~40 dòng)

  • Embed server không có route /assistants/*, nhưng adapter bắt buộc gọi 3 endpoint để khởi động.
  • search: trả metadata tĩnh từ registry graph — config: {} là bắt buộc, adapter dereference .configurable vô điều kiện.
  • graph: JSON của compiled graph → adapter lọc tên node khỏi stream.
  • schemas: trả null — adapter rơi về bộ key mặc định.
services/langgraph-embed-app.ts 
shim.post('/assistants/search', ... ids.map(id => ({
  assistant_id: id, graph_id: id, name: id,
  config: {}, // thiếu → TypeError trong adapter
  metadata: {}, version: 1, ...
})));
shim.get('/assistants/:id/graph',
  async c => c.json((await g.getGraphAsync()).toJSON()));
shim.get('/assistants/:id/schemas',
  c => c.json({ config_schema: null, ... }));

07 · B4 — trái tim của mô hình bảo mật

withVerifiedRunClaims

  • Server đầy đủ copy header x-* vào configurable (applyRequestHeadersToRunConfig) — embed không làm.
  • Adapter thì lọc rơi key lạ khỏi payload → hai phía cộng lại = graph mù danh tính.
  • Fix: rewrite body mọi POST /runs* — xóa x-agent-* client gửi (chặn giả mạo tenant), chèn claims từ header đã verify.
Bug thật 22/07: thiếu đoạn này → RUN_ERROR: Trusted agent context is unavailable khi tool chạy, và transcript âm thầm không ghi.
services/langgraph-embed-app.ts 
const configurable = { ...body.config?.configurable };
for (const key of Object.keys(configurable))
  if (key.startsWith('x-agent-'))
    delete configurable[key];   // chống spoof

for (const key of AGENT_CLAIM_HEADERS) {
  const value = request.headers.get(key);
  if (value) configurable[key] = value; // verified
}
// body mới → embed → createStubRun spread
// → runtime.configurable trong middleware/tools

08 · Chi tiết dễ vấp — mount prefix

Dispatch thủ công vào embed

  • Muốn rewrite body thì không dùng app.route được → phải embed.fetch(request mới).
  • Nhưng BFF mount app tại /langgraph, còn embed route từ / → phải strip prefix trước khi dispatch.
  • Prefix lấy từ routePath của Hono → chạy đúng cả khi mount ở root (harness cũ) lẫn /langgraph (production).
Bug thật 22/07 (thứ 2): quên strip → 404 POST /langgraph/threads not implemented. Harness khi đó mount ở root nên không phát hiện — bài học: harness phải giống production đến cả hình dạng mount.
services/langgraph-embed-app.ts 
app.all('*', async (c) => {
  const url = new URL(c.req.raw.url);
  const prefix = c.req.routePath.replace(/\/\*$/, '');
  if (prefix && url.pathname.startsWith(prefix))
    url.pathname = url.pathname.slice(prefix.length);

  let body = await c.req.raw.text();
  if (POST && RUN_CREATE_PATH.test(url.pathname))
    body = withVerifiedRunClaims(body, headers) ?? body;

  return embed.fetch(new Request(url, {...}));
});

09 · B5 — phía graph nhận danh tính

durable-memory → workspace-tools

  • resolveTrustedContext(runtime) đọc claims từ runtime.configurable → dựng agentContext vào state (userId, email, roles, threadId).
  • Tool chỉ được quảng cáo cho model khi API_BASE_URL có — không có API thì không có tool chết.
  • wrapToolCall: model chỉ chọn tool + args; danh tính bơm từ context verified, args của model không bao giờ quyết định "ai đang gọi".
  • Lỗi API (401/timeout) → ApiClientError → chuyển thành text cho model đọc, không sập run.
middleware/workspace-tools.ts 
wrapToolCall: async (request, handler) => {
  const agentContext = request.state.agentContext;
  const accessToken  =
    request.runtime.configurable['x-agent-access-token'];
  if (!agentContext || !accessToken)
    throw new Error('Trusted agent context is unavailable');

  const identity = { ...agentContext, accessToken };
  return executeWorkspaceTool(name, args, identity);
}  // model không bao giờ cung cấp userId

10 · B6 — persistence: 3 loại dữ liệu, 1 chỗ chứa

D1 qua memory worker

Thread metadataD1ThreadSaver/v1/thread-store/*thread_store (migration 0005)chỉ ALS — get miss → 404
Transcript chatdurable-memory middleware/v1/memory/*bảng transcript sẵn cóagentContext.userId
Vì sao cần AsyncLocalStorage? LangGraph tự sinh config nội bộ (getState, resume-at-head) không mang claims — những call đó vẫn phải biết tenant. ALS được set một lần ở B3, mọi tầng dưới đọc được mà không cần truyền tay.
Vì sao patch bằng json_patch trong SQL? ThreadSaver có semantics set(kind: 'put' | 'patch') — patch merge metadata ngay trong upsert, tránh round-trip đọc-sửa-ghi.

11 · Mô hình bảo mật — tóm gọn

Một nguồn danh tính duy nhất

  • Danh tính chỉ sinh ra tại requireAgentUser (verify chữ ký) — mọi nơi khác chỉ tiêu thụ.
  • Client gửi thẳng /langgraph với claims giả trong body? → withVerifiedRunClaims xóa sạch rồi ghi đè.
  • Model đòi đọc dữ liệu user khác qua args? → tool bỏ qua args danh tính, dùng context verified.
  • x-agent-access-token không bao giờ được log và không nằm trong graph state (chỉ trong configurable).
luồng danh tính 
Firebase ID token (browser)
   │ verify JWKS
   ▼
x-agent-* headers  ← nguồn sự thật
   ├─→ ALS(userId)        → D1 scoping
   ├─→ config.configurable → graph/tools
   └─→ Bearer → space-api  → as-user

✗ body client  ✗ args của model  — bị chặn/bỏ qua

13 · Hai bug một ngày — bài học

Chi phí thật của vùng "tự bù"

  • Bug 1: claims không tới graph (adapter lọc + embed không đọc header). Lỗi chỉ nổ khi tool chạy; transcript hỏng âm thầm.
  • Bug 2: quên strip mount prefix khi dispatch thủ công → 404 toàn bộ threads/runs.
  • Cả hai đều nằm đúng phần code thay thế những gì server mặc định làm sẵn — đây là trade-off đã chọn, không phải tai nạn.
Bài học 1: harness regression phải giống production đến cả hình dạng mount — giờ gateway harness dùng chính createLangGraphEmbedApp, mount /langgraph, claims qua headerFactory.
Bài học 2: đường nào có thể fail âm thầm (durable-memory bỏ qua khi thiếu context) phải có check riêng — trusted-context-check sinh ra từ đây.
Bài học 3: debug bằng bisect: gọi thẳng embed bằng curl (qua) vs qua adapter (rớt) → khoanh thủ phạm trong 1 bước.
